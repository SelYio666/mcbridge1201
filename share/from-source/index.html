从零开始：用下载源手动安装 Minecraft

1.20.1 / 1.21.1 通用 · 从版本清单一路到能启动 · 不需要 GitHub
难度：进阶 磁盘：约 1 GB 耗时：20–40 分钟 结果：一个可被 PCL 导入的 .minecraft
先说明：普通玩家不用这么折腾——用官方启动器或 HMCL 下载即可。这份教程是给“想自己用源下载” 或“启动器坏了要手动救”的人看的。全部文件都来自公开源，下载后按 sha1 校验。
1

准备目录与工具

  • 新建目录，例如 D:\MC（后面所有文件都放这里）；
  • 需要：浏览器或 curl、Python 3（用来跑下载/校验脚本）、Java（第 6 步再装）；
  • 本文用 1.21.1 举例，把命令里的版本号换成 1.20.1 即可。
mkdir D:\MC
cd /d D:\MC
2

拿版本清单，找到目标版本

所有版本都从同一份清单开始：

https://piston-meta.mojang.com/mc/game/version_manifest_v2.json

在里面找 "id": "1.21.1"，复制它的 url 字段（这是该版本的 JSON），下载为 1.21.1.json。

# Windows PowerShell 一行找 URL
(Invoke-RestMethod https://piston-meta.mojang.com/mc/game/version_manifest_v2.json).versions |
  Where-Object id -eq '1.21.1' | Select-Object -ExpandProperty url

这个 JSON 里包含：客户端 jar 地址、全部库、资源索引地址、启动主类。

3

下载客户端 jar

看版本 JSON 的 downloads.client：url 是下载地址，sha1 用来校验。

# 以 1.21.1 为例（地址以 JSON 为准）
curl -L -o 1.21.1.jar "<downloads.client.url>"
# 校验
Get-FileHash .\1.21.1.jar -Algorithm SHA1   # 与 JSON 里 client.sha1 对比
别自己拼 jar 地址——版本 JSON 给的就是权威地址，换版本时也以它为准。
4

下载库（libraries）

版本 JSON 的 libraries[] 每项都有 downloads.artifact： path（相对 libraries/ 的路径）、url、sha1。

把每个 artifact 下载到 libraries\<path>；Windows 还要处理 classifiers/natives-windows 的本地库（解压 dll 到 versions\1.21.1\natives）。

# 伪代码：遍历 version json
for lib in data["libraries"]:
    art = lib.get("downloads", {}).get("artifact")
    if art: download(art["url"], "libraries/" + art["path"], sha1=art["sha1"])
漏库 = 启动时 ClassNotFoundException。按 path 放，不要自己改名。
5

下载资源（assets）

版本 JSON 的 assetIndex.url 是资源索引；索引里 objects 的每个 hash 对应一个文件：

资源地址：https://resources.download.minecraft.net/<hash前2位>/<hash>
存放位置：assets\objects\<hash前2位>\<hash>
资源索引：assets\indexes\<assetIndex.id>.json
# 最小可用脚本
import json, os, urllib.request, hashlib
idx = json.load(open("assets_index.json"))
for name, o in idx["objects"].items():
    h = o["hash"]; dst = f"assets/objects/{h[:2]}/{h}"
    if os.path.exists(dst): continue
    os.makedirs(os.path.dirname(dst), exist_ok=True)
    urllib.request.urlretrieve(f"https://resources.download.minecraft.net/{h[:2]}/{h}", dst)

1.21.1 约 3900 个对象、900 MB；慢就换镜像（见第 8 步）。

6

装对应版本的 Java

版本Java
1.16.5 及更早8
1.18 – 1.20.4（含 1.20.1）17
1.20.5+（含 1.21.1）21
java -version   # 确认大版本号
7

摆好目录，启动

最后的结构应该是：

D:\MC\
  versions\1.21.1\1.21.1.json
  versions\1.21.1\1.21.1.jar
  versions\1.21.1\natives\      （Windows 的 dll）
  libraries\...
  assets\indexes\...
  assets\objects\...

启动需要正确的 classpath、主类（net.minecraft.client.main.Main）、资源索引名、 账号参数与 natives 路径——手写很容易错，建议用脚本或启动器启动。

# 用本项目的启动器（它读的就是这些源与目录）
python launcher/mclaunch.py verify 1.21.1 "D:\MC"
python launcher/mclaunch.py launch 1.21.1 "D:\MC" 你的名字

或者直接把 D:\MC 当游戏目录导入 PCL / HMCL 启动。

8

下载慢：换镜像

BMCLAPI 是社区镜像（非官方），路径和官方一一对应，把域名换掉即可：

资源：https://bmclapi2.bangbang93.com/assets/<hash前2位>/<hash>
Maven：https://bmclapi2.bangbang93.com/maven/<相对路径>

镜像会波动；失败就重试或换回官方。加载器 Maven（Fabric/Forge/NeoForge）和 Mojang CDN 是不同线路， 一边慢不代表另一边慢。

9

验收与常见错误

  • mclaunch verify 显示 version json / client jar / libraries / natives / assets 全 ok；
  • 能进入主菜单、能新建世界。
现象原因
ClassNotFoundException库没下全 / path 放错
UnsupportedClassVersionErrorJava 版本不对（1.21.1 要 21）
Missing assets / 无材质资源对象没下全，或 index 名对不上
启动参数报错classpath/主类/assetsIndex 拼错，用启动器更省事
