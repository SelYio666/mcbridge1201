# p117 — 下载路径冷/热对照（有界基准）

日期：2026-10-22。目的：在决定“要不要为了连接复用引入 httpx”之前，先拿到本机、本网络下
下载路径的真实数据。**这不是完整安装验证**：完整 assets 有 3,900+ 对象，两版冷/热会占用数 GB
与一小时以上，因此只测代表性链路，范围写在下面。

## 方法

- 工具：`tools/bench_download.py`（默认下载完**自动删除** root；`--keep` 才保留）；
- 每个版本在同一 root 上跑两遍：
  - **cold**：空目录，真实下载；
  - **hot**：文件已存在，走 SHA-1 短路（每轮清掉进程内 JSON/侧车缓存，避免把 HTTP 缓存
    当成文件缓存）；
- 链路：客户端 jar → **全部**当前平台允许的 libraries（与 `install_vanilla` 同过滤/同并发 8）
  → assets 样本（索引按名字排序前 150 个，并发 24，与正式安装一致）
  → Fabric Loader profile 安装（元数据 + 8 个库）；
- 指标：墙钟、字节、MB/s、下载数、**失败尝试数**（不是失败文件数）、重试次数、实际域名。

## 结果（2026-10-22 00:35–00:46）

| 版本 | 阶段 | cold | hot |
|---|---|---:|---:|
| 1.20.1 | 客户端 jar | 68.22 s / 30.4 MB / 0.45 MB/s | 0.02 s |
| 1.20.1 | libraries（64） | 113.61 s / 58.1 MB / 0.51 MB/s | 0.22 s |
| 1.20.1 | assets 样本（150） | 101.21 s / 85.2 MB / 0.84 MB/s | 0.08 s |
| 1.20.1 | Fabric（8 库） | 36.03 s / 4.3 MB | 13.38 s（0 字节） |
| 1.21.1 | 客户端 jar | 8.59 s / 25.6 MB / 2.98 MB/s | 0.02 s |
| 1.21.1 | libraries（70） | 211.56 s / 63.6 MB / 0.30 MB/s | 0.25 s |
| 1.21.1 | assets 样本（150） | 135.32 s / 84.8 MB / 0.63 MB/s | 0.07 s |
| 1.21.1 | Fabric（8 库） | 40.76 s / 4.4 MB | 13.05 s（0 字节） |

- 冷启动（客户端 + 全部库 + 150 资源 + Fabric）大约 **5.3 分钟（1.20.1）/ 6.6 分钟（1.21.1）**；
  按同样速率外推 3,900 个资源会明显更久，所以本轮没有下全量 assets；
- 失败尝试：1.20.1 cold 客户端 1 次、库 4 次、资源 5 次；1.21.1 cold 库 6 次、资源 33 次。
  **全部在同源重试后成功**（阶段没有失败文件），说明“重试 + 快速换源”确实必要；
- 本轮所有成功下载的最终域名都是官方（`piston-data.mojang.com` / `libraries.minecraft.net` /
  `resources.download.minecraft.net` / `maven.fabricmc.net`），BMCL 镜像这轮没被用到；
- hot：文件检查几乎为 0；Fabric 的 13 s 全是元数据/侧车（hedged 请求各约 3 s + 侧车取摘要），
  不是重新下载。

## 结论：本鱼不引入 httpx 连接池

1. **冷路径是带宽/单源限速瓶颈，不是连接数瓶颈**：单流客户端 0.45–2.98 MB/s，
   24 线程资源聚合 0.63–0.84 MB/s，没有随并发显著上升。连接池能省 TLS 握手，
   但在这条链路上不会把 0.3 MB/s 变成几 MB/s；报告本身也要求先对照测试。
2. **真正的卡点在“坏源等待”和“元数据/sidecar”**，本轮已经用更便宜的改动解决：
   - 元数据改成**对冲请求**：官方 3 秒未回就并行打镜像，谁先成功用谁；
   - 元数据 15 分钟 TTL 缓存；
   - maven `.sha1` 侧车缓存到 `<jar>.sha1`，取不到时退化为**本地摘要** `<jar>.local.sha1`
     （只做完整性、不宣称上游真实性），hot Fabric 从 40.6 s 降到 13 s；
3. 引入 httpx 需要新依赖、便携包变大，且当前证据不支持“收益 > 成本”。如果以后要试，
   应先按报告要求做配对测试（同机同网、冷/热各 3 组），并保留回退开关。

## 边界

- 只测 150 个资源样本，不是全量 assets；没有执行“完整安装 → 进游戏”；
- 只测一次冷/热（报告建议 3 组配对），网络本身波动大（同一客户端 8.59 s vs 68.22 s），
  数字只能说明量级，不能当带宽承诺；
- Fabric 只测 Loader profile 安装，不含 Fabric API 模组文件（BMCL 对 Fabric API 仍 404）；
- Forge/NeoForge 安装器由第三方库/Java 安装器处理，不在这条基准内。
