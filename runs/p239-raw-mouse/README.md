# p239 — 关掉 rawMouseInput 也抓不住：最后一个假设被否掉

日期：2026-11-03。p238 用“视角转动”判断抓取失败后，本鱼想到一个可检验的解释：
`options.txt` 里是 `rawMouseInput:true`，MC 走 Windows 原始输入（`WM_INPUT`），而
`mouse_event`/`SetCursorPos` 产生不了原始输入事件——所以即使抓住了光标、合成移动也转不动视角。

## 做法

- 备份游戏根目录的 `options.txt`，把 `rawMouseInput:true` 改成 `false`；
- 一次性副本 `p239-world`，quickplay 进世界；
- 点击窗口中心 → 移动鼠标 → 比截图判断视角是否转动；
- 结束时**还原** `options.txt`（`options.txt.before` 留档）。

## 结果（`result.json`）

| 检查 | 结果 |
|---|---|
| 进世界 / 前台 | ✅ |
| 关掉 raw 输入后，移动鼠标相机转动 | ❌ **false，差异 0.13**（比 p238 的 1.68 还低） |
| 背包打开 | ❌ 未验证（前置不成立） |

## 结论

- **rawMouseInput 不是原因**：关掉它之后，合成移动依然不转视角；
- 结合 p235/p237/p238：三种尝试（光标回收判据、视角判据、关 raw 输入）都没能让 MC 进入光标抓取状态；
- 合成点击在**菜单**里是有效的（p234 点开过界面），在**世界内**却建立不了抓取；
  原因本鱼现在查不出来，**不再继续试探**，这条按“未验证/边界”挂着，不用改代码绕过去；
- 聊天键不受影响（p235 已验证）。

## 边界

- 单客户端、1.20.4 原版、单显示器；
- `options.txt` 已还原，未留副作用（`options.txt.before` 可对比）；
- 判据是画面差异（160×90 缩略图平均通道差），阈值 3。
