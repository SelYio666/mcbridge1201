# p123 — 真实 `mirror` 模式（有界）验证

日期：2026-10-22。目的：验证新增的“镜像优先”下载源不是纸面功能。

## 为什么是“有界”

先试了 `mirror` 模式的全量 1.21.1 安装：BMCL 的资源对象限速明显，跑到 **222 MB / 10 分钟**
还没完，按这个速度 3,911 个资源要一两个小时，于是中止并删掉半成品（不占磁盘）。
改为有界链路：**客户端 jar + 全部允许库 + 120 个资源样本 + Fabric profile**，
这正是 `mirror` 模式需要证明的路径组合。

## 结果

| 指标 | 值 |
|---|---:|
| 总耗时 | **488.8 s**（BMCL 明显慢于官方直连） |
| 文件 / 字节 | 203 / 167,779,977 B（约 160 MB） |
| SHA-1 校验 | **191 个文件全部匹配，0 缺失** |
| 下载事件 | 305 次（288 走镜像，17 回退官方） |
| 失败尝试 / 重试 | 105 / 122（全部重试后成功） |
| Fabric profile | `fabric-loader-0.19.5-1.21.1` |

最终 host 分布说明 BMCL 会在多个节点间跳转（`mirror.nyist.edu.cn`、`*.sakura.sld.tw`、
`minio.749333.xyz` 等），官方兜底命中 `resources.download.minecraft.net`、
`maven.fabricmc.net`、`piston-data.mojang.com`——**“官方优先”在 mirror 模式仍是最后保险**。

健康文件 `runs/p123-mirror-mode-install/install.json` 的 `health` 字段记录：
`bmclapi2.bangbang93.com` 出现 2 次近期失败，官方各 host 均为 0。

## 结论

- `mirror` 模式**真的会走镜像**（288/305），并且镜像节点失败时能回退官方；
- 镜像并不等于更快：本次比官方直连的全量安装（p118 的 115 s）慢得多，且失败尝试多；
- 因此保持 **auto（官方优先）为默认**，`mirror` 只给“官方源被墙/不可达”的用户；
- 健康缓存确实有内容（`bmclapi2` 失败计数），会参与 `auto` 模式的排序。

## 清理

有界测试的 root 已删除（`root_cleaned: true`）；中止的全量半成品（222 MB）也已删除。

## 限制

- 不是完整安装（没有 3,911 个资源、没有进游戏）；完整性由 p118（1.21.1，官方）和
  p122（1.20.1，官方）覆盖；
- 单次网络采样，BMCL 节点/时段不同结果会变；
- 只测 `1.21.1`，未测 1.20.1 的 mirror 模式。
