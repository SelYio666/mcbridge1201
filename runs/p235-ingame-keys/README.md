# p235 — 游戏内真实键盘：聊天开/关通过；背包键受“光标抓取”门控

日期：2026-11-03。目标：在 p234（菜单级真实键鼠）之后，把真实键盘推进到游戏内。

## 结论

| 检查 | 结果 |
|---|---|
| 进入世界（quickplay，一次性测试存档） | ✅ |
| 按键前窗口在前台 | ✅ 不在前台就不发按键 |
| `T` 打开聊天（真实 `SendInput` + 扫描码） | ✅ 底部区域差异 **10.41** |
| `Esc` 关闭聊天 | ✅ 关闭后差异回落到 **1.46** |
| 光标是否被游戏抓取 | ❌ **false**（见下） |

## 发现：合成点击抓不住光标

- 测试里先尝试用真实 `mouse_event` 点击窗口中心来让 MC 进入“鼠标抓取”状态（最多 3 次，每次用
  “把光标移到角落、看游戏会不会把它吸回中心”做判据），**三次都是 false**；
- 原版把 `keyInventory`（背包）和 `Esc`（暂停菜单）放在 `handleKeybinds()` 里，而这条路径需要抓取状态；
  聊天键 `T` 在 `keyPressed()` 里直接处理，所以没被抓取也能开；
- 因此本回合**只声称聊天键可用**：背包/暂停键用这条合成输入路径测不了，不是“按键无效”，
  而是抓取状态没建立。

这条结论和 p191/p192 的“合成输入在 GLFW 回调边界”是同一类边界，写进 remaining-work。

## 安全约束

- 每次按键前断言 `GetForegroundWindow() == 游戏窗口`，不满足就退出、不发输入；
- 用 `p229-world` 的**一次性副本** `p235-world`，不碰玩家存档；
- 聊天开/关不会写世界数据；本回合没有破坏方块、没有移动。

## 另一个技术细节

字母键必须用 **带扫描码的 `SendInput`**：`keybd_event(vk, 0, 0, 0)`（扫描码 0）在这个 GLFW 版本里
对字母无效（第一次跑聊天就没打开）。`MapVirtualKeyW(vk, 0)` 取扫描码后正常。
